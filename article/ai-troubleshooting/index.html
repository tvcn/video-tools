症状排障：手、脸、闪烁、文字、音画不同步

先按症状定位，不要一上来换模型。手、脸、闪烁、文字、同步五类问题，各有不同的修法；换模型通常是最后一步。

适用与不适用 / Fit and no-fit

  • 生成结果有具体缺陷，需要快速定位。
    Generations with specific defects needing a quick diagnosis.
  • 团队要一张“症状→原因→修法”的表。
    Teams needing a symptom→cause→fix table.
  • 不适用：没有具体样本、只想问“哪个模型好”。
    Not for: no sample, only “which model is best.”

怎么做 / Do this

  1. 先复现：同提示/同参考/同参数跑 3 次。
    Reproduce: same prompt/reference/settings three times.
  2. 按症状查表：手/脸/闪烁/文字/同步。
    Look up symptom: hands/face/flicker/text/sync.
  3. 先改一个变量：参考/动作/光/分辨率。
    Change one variable: reference/action/light/resolution.
  4. 仍失败再换模型/后期修。
    Only then change model or fix in post.
  5. 记录失败类型，进项目库。
    Log failure type into the project library.

别踩 / Avoid

  • 一上来换模型；问题是参考图。
    Changing models first; the issue is the reference.
  • 一次改五个变量；无法归因。
    Changing five variables; cannot attribute.
  • 不记录失败；下次再踩。
    Not logging failures; repeat next time.

继续往下 / Go deeper

排障的第一原则是“先复现”。一条失败可能是随机，三条同题都失败才是模式。复现后再改一个变量；否则你永远不知道是哪一项修好的。

换模型应该是最后一步，因为成本最高。参考图、动作幅度、光向、分辨率、后期修，这五个便宜手段先试；都不行再换模型。

验收 / Checks

  • 同题复现 3 次，确认不是偶发。
    Three runs confirm it is not random.
  • 一次只改一个变量。
    One variable changed at a time.
  • 症状/原因/修法有记录。
    Symptom/cause/fix recorded.
  • 换模型是最后一步，不是第一步。
    Model change is last, not first.

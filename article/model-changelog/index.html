适用与不适用 / Fit and no-fit

  • 制片/采购：每季度复核一次模型池。
    Producers/procurement: review the model pool quarterly.
  • 内容团队：交付前确认版本仍可用。
    Content teams: confirm the version is still available before delivery.
  • 不适用：需要完整跑分/排行榜的读者。
    Not for: readers wanting lab scores or leaderboards.

怎么做 / Do this

  1. 只记录五类变更：版本、价格、能力、地区、停运。
    Log five change classes: version, price, capability, region, retirement.
  2. 每条写日期、官方链接、影响的项目类型。
    Each entry has date, official link and affected project types.
  3. 价格标“读取日期”，不写“永久价”。
    Prices carry a read date, never “permanent.”
  4. 停运前 60 天发迁移提醒。
    Send migration notice 60 days before retirement.
  5. 每季度把旧条目归档，不删历史。
    Archive old entries quarterly; never delete history.

别踩 / Avoid

  • 把发布会当交付承诺；上线时间经常跳票。
    Treating a launch event as a delivery promise; dates slip.
  • 只记价格不记地区；同一模型不同地区价格/可用性不同。
    Logging price without region; price and availability differ.
  • 删除旧条目；无法解释旧项目为什么换模型。
    Deleting old entries; cannot explain why a project changed models.

继续往下 / Go deeper

变更日志不是新闻流。它只回答三个问题：现在还能不能用、价格有没有变、旧项目要不要迁移。发布会、演示片、第三方评测都不进日志；它们可以作为线索，但不能当交付依据。

模型生命周期要写进合同：版本号、停运通知期、替代模型、旧素材导出责任。没有这四项，停运时只能临时救火。把日志链接放进项目看板，比在群里转发截图可靠。

验收 / Checks

  • 每条有日期和官方链接。
    Every entry has a date and official link.
  • 五类变更都有覆盖，不只记价格。
    All five change classes covered, not only price.
  • 停运条目有迁移替代和截止日。
    Retirement entries include migration alternative and deadline.
  • 价格条目有“读取日期”。
    Price entries carry a read date.

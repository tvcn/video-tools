Model comparison: write the protocol before watching the footage

“Which model is better” has no universal answer. A useful comparison fixes input, duration, resolution and review question; otherwise it is two different style reels. Model versions change fast in November 2026, so any score needs a date and version.

Fixed itemHowIf not fixed
PromptSame text, word for wordTests prompt-writing, not the model
Duration / resolutionSame length and ratioLonger clips reveal more artifacts
Review questionOnly hands, text, motionTurns into taste
VersionModel name, date, quotaNot reproducible next month

A four-shot test set

  1. Character turns: face, hands, wardrobe continuity.
  2. Handheld product: text, logo, finger count.
  3. Fast motion: blur, background tearing.
  4. Locked still life: material, light, detail stability.

Each shot gets pass/fail, not “looks better.” If it fails, do not put the sample in a client pitch. State the conclusion as “under this test set, this version, this date,” and do not generalize.

On set

Test five models with the same five-second prompt and reference image. Run each three times and score face, hands, text, and motion.

Do this

Model comparison is not a leaderboard; test the shot types you need: face, hands, motion, text, long take.

  1. Use the same five-second prompt and reference image across five models.
  2. Run each model three times and log face, hands, text, and motion.
  3. Score against your project weights, not the overall ranking.

Avoid

Do not choose by overall rank; your shot type is the scorecard.

Decision tree: choose by shot type, not leaderboard

Model comparisons are easily distorted by rankings. Write the shot type first: talking head, product, motion, character consistency, text/graphics. Different tasks demand different models; no model is first in all five.

  1. Write shot type, duration and input mode (text/image/video).
  2. Choose three pass lines: face stability, hand error rate, motion continuity.
  3. Run each model three times and count usable seconds, not “feel”.
  4. Rank by project weight, then check price and rights.

Test scope: same prompt, same reference, three runs

Use one five-second prompt and one reference image across five models, three runs each; count only usable seconds. Log model version, resolution, generation time and failure reason. Not measured: lab image-quality scores or blind audience ratings.

Add: failure cases

Counting generations instead of usable seconds distorts every model comparison. These five mistakes are common.

MoveResultReplace with
Choose by overall rankingYour shot type may be the weak spotRun three times by shot type
Judge a single frameMotion breaks or flickers immediatelyWatch the full five seconds
One run per promptRandomness looks like stabilityThree runs, same prompt/seed
No version logNext week’s result cannot be reproducedLog version/resolution/time
Count generated seconds as usableCost is underestimated by multiplesCount only deliverable seconds

Cost per usable second, not per generation

Break one generation into subscription/credits + human selection + retries + post repair. Counting only the first two underestimates cost. If one of three five-second shots is usable, the real cost is three times the list price; add half an hour if hands need repair. Compare cost per delivered second, not per generation.

Versions, prices, rights and watermark rules change. This page records public specs and local short tests; not done: blind audience scores or lab image-quality scores. Re-run the same prompt set quarterly and update the conclusion.

Last line: treat a model as a lens, not magic

A model is not “one sentence in, one film out”. It is closer to an unpredictable lens: measure its breathing, motion, weaknesses and cost before deciding which shot it can carry. Run three generations, count usable seconds, then put that number into the budget. A leaderboard tells you how others choose; it does not tell you whether your shot can be delivered.

  • Write the shot type before choosing a model.
  • Count usable seconds before comparing unit price.
  • Log failure before logging success.

Boundary: generation does not replace shooting decisions

A model can create pickups, references and impossible shots, but it cannot replace on-set light, performance and spatial relations. Use generation as previz, then decide which shots must be practical; put “generation failure” on the shot list instead of gambling in post.

  • Previz: test framing and motion with the model.
  • Practical: people, light and space still follow set physics.
  • Fallback: every failed generation has a practical alternative.

Add: one line

The end of model selection is not a leaderboard; it is the class of shot you can deliver repeatedly. Remove the shots you cannot deliver and the budget becomes clear; run the deliverable shot three times before paying more for it.

3 checks

  • All five models use the same prompt and same reference image.
  • Each model runs three times with face, hands, text, and motion logged.
  • Final ranking follows project weights, not the leaderboard.

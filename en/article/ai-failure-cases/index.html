AI Failure Cases: Name the Mistake

Name whether the failure was prompt, model, or post. "AI sucks" teaches nothing.

Failures usually start with unlocked input

Common failures: wardrobe changes per shot, finger count, garbled background text, reversed motion, mismatched light. Most trace to inconsistent references, overloaded prompts or no shared anchor between shots.

Keep a failure sheet: shot, problem, likely cause, next variable to change. Do not just write “AI is bad.”

Limits

Failure cases are not a rejection. They map the boundary: which shots must be live, which can be generated. Classify before discussing efficiency.

On set

Log four causes: prompt, model version, reference, and post. Reproduce once to tell whether the prompt or the model failed.

Do this

An AI failure case names whether the prompt, model, or post caused it; “AI sucks” teaches nothing.

  1. Log four elements: prompt, model version, reference, post.
  2. Reproduce once and confirm whether prompt or model caused it.
  3. Write one executable fix, not just “do not use AI.”

Avoid

Do not blame the model for every failure; prompts and post create the same breaks.

3 checks

  • The failure log has prompt, model version, reference, and post.
  • It reproduces once and identifies which element caused it.
  • The conclusion is one executable fix, not “AI sucks.”

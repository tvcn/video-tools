Backup Recovery: Rehearse One Restore

Backup is not finished when the copy ends; restore one random file to prove it.

On set

Use 3-2-1: three copies, two media types, one offsite. Restore one random file to another machine and open it.

Do this

A backup is not done until a random file restores. Test recovery, not just copying.

  1. Follow 3-2-1: three copies, two media types, one off-site.
  2. Restore one random file to another machine.
  3. Open it, confirm playback or relink, and record the recovery time.

Avoid

Do not copy without restoring; a failing drive does not warn you.

Put 3-2-1 on the desk

Three copies: card/in-camera, on-set SSD and backup drive. Two media types: SSD/HDD or LTO. One offsite: cloud or another building. RAID is not backup; it survives a dead drive, not deletion, ransomware or fire.

  1. Checksum the card copy before formatting. Do not wipe the card until two readable copies exist.
  2. Power and carry the on-set SSD and backup drive separately; never in the same bag.
  3. Check the backup log at wrap. Rerun a failed job immediately; do not wait until the studio.

Restore drill

  1. Pick a random file, not the one just copied; restore it from the backup to another machine.
  2. Open or relink it and confirm it plays and imports into the NLE. File size alone is not proof.
  3. Log restore time, path and checksum; have a different person run the next drill.

Drill quarterly, and at least once before a project delivery.

Fake backups

  1. RAID as backup: a second drive dies during rebuild and everything is gone. RAID is not version history.
  2. Sync as backup: delete locally and the cloud deletes too. Sync is not backup.
  3. Backing up only in the same building: fire or flood takes both. Offsite must be offsite.
  4. Copying without checksums: a bad file passes silently until someone opens it.

Backup acceptance log

  • Three copies, two media types and one offsite copy are identifiable; each has a checksum.
  • A random file restores on another machine and plays or relinks.
  • Restore time, steps and checksum are logged; another person can repeat it.
  • Two readable copies exist before card formatting; the backup log has no failed jobs.

Restore log

Every drill logs date, random file, source drive, checksum, target machine, open result, duration and operator. A drill without an open result does not pass.

3 checks

  • Three copies, two media types, and one off-site copy can all be named.
  • A random file restores on another machine and opens.
  • Recovery time and steps are logged so the next test repeats them.

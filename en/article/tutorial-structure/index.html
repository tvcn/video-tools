Tutorial Structure: One Problem, One Skill

One problem, one skill. Three tricks in one tutorial means none is learned.

The first five seconds must show what “finished” looks like, or the viewer cannot decide whether to learn. Then state the starting point and prerequisites before step one; each step solves one problem.

Show the result before the steps

Enlarge the step that most often fails and show the wrong result. Viewers do not forget the correct step; they do not know what wrong looks like.

Limits

A tutorial is not a feature list. Every step needs “what proves it worked”; without a check, the viewer is guessing.

What happened

  1. The first version walked through every menu item for eight minutes. Test viewers paused at minute two, unsure of the goal.
  2. We showed the result first: the final file in the first ten seconds, then three steps backwards. One shortcut per step.
  3. Every “by the way” branch was cut. Common failures moved to a 30-second end block, not the main path.

The trade-off

We did not chase “all features,” only one path that works. The mouse path is uncut so viewers can follow; narration is 10% slower and each step gets one second of silence. The end card is a three-item check, so viewers can judge their own result.

Reusable / not transferable

  • Reusable: show the result first, then the shortest path; one tutorial teaches one testable action.
  • Not transferable: software changes. Record the current menu names and mark the version; old tutorials need a version warning.

On set

Teach one action: import media and set proxies. Do not also teach grading and subtitles.

Do this

A tutorial teaches one thing; three tips at once means the viewer learns none.

  1. Teach one action: import footage and set proxies.
  2. Show the finished result before breaking down steps.
  3. Do not also cover grading and subtitles.

Avoid

Do not ramble while operating; viewers are following along.

Judge

This page passes on three observable checks, not slogans:

  • 1. The whole piece teaches one action named in the title.
  • 2. The finished result appears before steps.
  • 3. No second topic such as grading or subtitles interrupts.

Failures

Any one of these means stop and fix it before post:

  • 1. Check 1 is only staged (“The whole piece teaches one action named in th…”); another camera position or location exposes it.
  • 2. Check 2 is left to post or a verbal explanation (“The finished result appears before steps”); nothing on set can be rechecked.
  • 3. Do not ramble while operating; viewers are following along.

Extend

10-minute exercise: Break down one 30-second reference, mark the timecodes for “Teach one action: import footage and set proxies.” and “Show the finished result before breaking down steps.”, then answer: if one disappeared, would the film still hold?

Check

  • The whole piece teaches one action named in the title.
  • The finished result appears before steps.
  • No second topic such as grading or subtitles interrupts.

Deep dive

About 6 minutes. A tutorial is not a display of skill. It is proof that the viewer can do it too.

Show the result first

Show the finished result and the pass condition in the first ten seconds: what gets baked, exported, measured. Do not open with “hello, today I will share three tips.”

One problem, one lesson. Two goals in the title and the viewer no longer knows when they are done. State the final check up front and aim every step at it.

Three steps, one failure

Each step gets one action, one setting, one failure point. Close-up on hands, screen capture for the interface, hold the key number for three seconds. Do not read ten settings in one breath.

Do it once complete, then break it down. The viewer needs the continuous process, not ten isolated tricks. You can speed up repetition, but never cut the cause and effect.

Pass condition and template

End with a check the viewer can run: is the audio clipping, are subtitles over two lines, does the file open on the target machine? Add one common failure and its fix.

A downloadable checklist, settings sheet, or project file beats talk. If you cannot share a file, put the settings and order on screen so nobody has to pause and copy.

Five-minute drill: teach one friend once

Pick a task that takes three minutes and teach it in three steps. Put the finished result and pass condition first. Ask a friend who has never done it to follow your steps without your help.

Note the three places they stop: which step is unclear, which setting they missed, which failure you did not warn about. Add those three places to the video; only then is the tutorial done.

When it is done

Give someone who has not seen the video the footage and the materials, and say nothing. If they can produce the result and pass the check stated at the top, the tutorial is done. Where they get stuck, go back and add a close-up or a setting for that step.

Ten tutorial checks

  • Finished result in ten seconds
  • One problem, one lesson
  • Pass condition stated up front
  • One action and one setting per step
  • Clear close-up or screen capture
  • Key number held for three seconds
  • Complete run before breakdown
  • Cause and effect never cut
  • Self-check at the end
  • Checklist or settings sheet provided

A tutorial succeeds when the viewer can produce a checkable result after the video ends.

Post speed is not software; project structure, proxies and versions tell everyone where the latest file is. One page of &quot;Project Structure: Folders Beat Software&quot; solves one local problem; joining &quot;Project Structure: Folders Beat Software&quot;, &quot;Proxy and Cache: Do Not Fill the Drive First&quot; and &quot;Versioning: Never Name It Final&quot; exposes the real failure: conditions are missing, too many variables move, and the result cannot be reproduced.

Problem

The problem is not a lack of methods; each step works alone, but together they fail because the condition was not written, too many variables moved and the result cannot be reproduced.

The order is condition, judgement, one variable and evidence. A step is complete only when the next person can repeat it.

Judgement

  • First gate in "Project Structure: Folders Beat Software": The four root folders exist and media, project, exports, and docs each live in place.
  • Second gate in "Proxy and Cache: Do Not Fill the Drive First": Filenames carry date, scene, and camera and sort cleanly.
  • Third gate in "Versioning: Never Name It Final": On another machine or app, the path still leads to the original media.

If one gate fails, return to its single page; do not hide an unsolved point inside a longer chain.

Method

  1. Write the condition first: turn "Create 01_media, 02_project, 03_exports, and 04_docs at the root." from "Project Structure: Folders Beat Software" into three rows: material, environment, acceptance.
  2. Run one minimal action: follow "Project Structure: Folders Beat Software" for 30 seconds and do not add the second page yet.
  3. Attach the second page: Name files date_scene_camera, never “final”..
  4. Use the third page as a control: Keep proxies and originals separate and back up the same day..
  5. Change one variable at a time; write the other conditions down instead of remembering them.
  6. Film the failure too: put failure and success side by side to see which step cannot be skipped.
  7. Ask the next person to reproduce from the record; if they cannot, the record is not finished.

Field test

A reproducible test, not a client case: take 30 seconds of material, make version A using "The four root folders exist and media, project, exports, and docs…" from "Project Structure: Folders Beat Software", then version B using "Filenames carry date, scene, and camera and sort cleanly." from "Proxy and Cache: Do Not Fill the Drive First"; only one variable may differ. Put them side by side and record what breaks first in "Versioning: Never Name It Final": condition, action or acceptance. If it works on the first try, add one real constraint and run it again.

Acceptance

  • The four root folders exist and media, project, exports, and docs each live in place.
  • Filenames carry date, scene, and camera and sort cleanly.
  • On another machine or app, the path still leads to the original media.
  • Proxies and cache sit on the second drive and the edit drive still has free space.
  • The system drive keeps at least twenty percent free with no red warning.
  • After clearing cache, the project rebuilds and every original remains.
  • The filename contains date, platform, duration, and version and sorts cleanly.
  • The log shows why each change happened and who approved it.
  • Pick an old version and you can state how it differs from the current one.
  • Filename has project, date, version, status

Alternatives

  • For a single-point problem in "Project Structure: Folders Beat Software", go back to Project Structure: Folders Beat Software; do not use the whole chain.
  • To compare two actions, read Proxy and Cache: Do Not Fill the Drive First and leave the third page alone.
  • For acceptance only, use Versioning: Never Name It Final as a self-test sheet.

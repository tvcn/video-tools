Master delivery: master, QC, platform

Delivery is not one export; master, QC and platform specs must align once or the launch comes back.

Delivery is not one export; master, QC and platform specs must align once or the launch comes back. One page of "Mastering: One File to Rule the Delivery" solves one local problem; joining "Mastering: One File to Rule the Delivery", "QC: Black Frames, Frozen Frames, Dead Audio" and "Platform Deliverables: One Master, Many Safe Areas" exposes the real failure: conditions are missing, too many variables move, and the result cannot be reproduced.

Problem

The problem is not a lack of methods; each step works alone, but together they fail because the condition was not written, too many variables moved and the result cannot be reproduced.

The order is condition, judgement, one variable and evidence. A step is complete only when the next person can repeat it.

Judgement

  • First gate in "Mastering: One File to Rule the Delivery": The master is the highest-quality format and its filename says master.
  • Second gate in "QC: Black Frames, Frozen Frames, Dead Audio": Every platform version traces back to the same master with no backward overwrite.
  • Third gate in "Platform Deliverables: One Master, Many Safe Areas": The master opens, plays, and relinks on a clean machine.

If one gate fails, return to its single page; do not hide an unsolved point inside a longer chain.

Method

  1. Write the condition first: turn "Make the master in the highest-quality ProRes or DNxHR and name it master." from "Mastering: One File to Rule the Delivery" into three rows: material, environment, acceptance.
  2. Run one minimal action: follow "Mastering: One File to Rule the Delivery" for 30 seconds and do not add the second page yet.
  3. Attach the second page: Derive platform, vertical, and subtitle versions from it; never edit backward..
  4. Use the third page as a control: Confirm the master opens, plays, and relinks before delivery..
  5. Change one variable at a time; write the other conditions down instead of remembering them.
  6. Film the failure too: put failure and success side by side to see which step cannot be skipped.
  7. Ask the next person to reproduce from the record; if they cannot, the record is not finished.

Field test

A reproducible test, not a client case: take 30 seconds of material, make version A using "The master is the highest-quality format and its filename says ma…" from "Mastering: One File to Rule the Delivery", then version B using "Every platform version traces back to the same master with no bac…" from "QC: Black Frames, Frozen Frames, Dead Audio"; only one variable may differ. Put them side by side and record what breaks first in "Platform Deliverables: One Master, Many Safe Areas": condition, action or acceptance. If it works on the first try, add one real constraint and run it again.

Acceptance

  • The master is the highest-quality format and its filename says master.
  • Every platform version traces back to the same master with no backward overwrite.
  • The master opens, plays, and relinks on a clean machine.
  • Black frames and freezes: watch from head to tail at 1x and log timecode.
  • Dropouts and peaks: listen with headphones, not just the waveform; check left/right and phase.
  • Subtitles: check safe area, typos, line breaks, timing and forced subtitles.
  • One master; every platform version traces back.
  • Each platform has frame, runtime, caption, and loudness specs.
  • Vertical is recomposed, not center-cropped.
  • All three caption types are played.

Alternatives

  • For a single-point problem in "Mastering: One File to Rule the Delivery", go back to Mastering: One File to Rule the Delivery; do not use the whole chain.
  • To compare two actions, read QC: Black Frames, Frozen Frames, Dead Audio and leave the third page alone.
  • For acceptance only, use Platform Deliverables: One Master, Many Safe Areas as a self-test sheet.

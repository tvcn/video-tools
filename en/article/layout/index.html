Layout: Camera and Asset Handoff

Layout locks camera, scale, and asset versions before animation. A vague handoff makes animators guess.

3D layout is not pretty placement. Draw the ground line, camera height and focal length first, then the character. With those three, space exists. Wrong scale makes later animation look pasted on.

Layout starts with camera and ground

Block a playblast with simple boxes, check occlusion and silhouette; do not add detail.

Limits

Layout is not the final shot. It can be rough, but camera, scale and timing must be locked; changing them later is the most expensive fix.

Layout: turn a shot into a handoffable space

Layout is not pretty composition. It fixes camera, blocking, scale and motion path so the next person does not guess. A usable layout shot can be picked up by another animator.

DeliveryMust stateCommon gap
CameraLens, position, path, frame countA still composition with no move
CharacterBlocking, facing, eye line, scaleScale does not match set
SetMovable props, occlusionForeground hides subject

Project-level checks

  1. Start with a grayscale blockout. Confirm silhouette and space before detail.
  2. Mark camera move with three keys: start, middle, end. “Push in” is not a path.
  3. Mark foot contact with the ground; floating feet are the most common layout failure.
  4. Give animation, lighting and comp a shot-to-asset map so same-name assets do not overwrite each other.

Review at final frame rate, not on stills. A beautiful still with bad motion means the layout path is wrong.

On set

Lock three things before handoff: camera, character scale, and asset version. Put the version in the file header and animate to the layout.

Do this

Layout locks camera, proportion, and asset version before handoff; unclear handoff makes animators guess.

  1. Lock three things: camera, character scale, asset version.
  2. Write the version number in the file header.
  3. Animate to the layout without changing the camera.

Avoid

Do not leave the camera live in layout; changing it after animation starts is rework.

Judge

This page passes on three observable checks, not slogans:

  • 1. Camera, character scale, and asset version are locked and versioned.
  • 2. The file header shows version and dependencies so animators do not guess.
  • 3. Animation does not change the camera and the final shot matches layout.

Failures

Any one of these means stop and fix it before post:

  • 1. Check 1 is only staged (“Camera, character scale, and asset version are…”); another camera position or location exposes it.
  • 2. Check 2 is left to post or a verbal explanation (“The file header shows version and dependencies…”); nothing on set can be rechecked.
  • 3. Do not leave the camera live in layout; changing it after animation starts is rework.

Extend

10-minute exercise: Draw three keys at 24 fps, change only “Write the version number in the file header.”, and export two seconds. If the weight still does not read, add anticipation before adding blur.

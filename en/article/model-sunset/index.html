Retired and superseded models

Sora web/app ended on 2026-04-26 and its API on 2026-09-24; Gen-3 Alpha and Turbo are also retired. Export old work, migrate the model, then retest.

Fit and no-fit / 适用与不适用

  • Teams with projects made on retired models needing redelivery or sequels.
  • Producers assessing migration risk before a new purchase.
  • Not for: brand-new projects with no legacy dependency.

Do this / 怎么做

  1. Export all old masters, prompts, references and project files.
  2. List dependencies: shots to regenerate vs shots to keep.
  3. Find one primary and one backup for each legacy shot.
  4. Rerun the same prompt three times and compare face/motion/audio.
  5. Update contracts, labels and delivery notes; remove old model names.

Avoid / 别踩

  • Assuming “retired = still works”; API calls fail after shutdown.
  • Exporting masters only, not prompts/references; cannot reproduce.
  • Copying parameters across models; motion breaks.

Go deeper / 继续往下

A sunset is project risk, not news. Sora web/app ended April 26 and API September 24; planning Sora shots in October is not a quality question but a delivery question. Add a lifecycle column to procurement.

Migration order is export, split dependencies, test replacements, then regenerate. It is not pasting old prompts into a new model. The value is in prompts, references and project structure, not the old master.

Checks / 验收

  • All masters, prompts, references and project files exported.
  • Every legacy shot has primary and backup models.
  • Replacement tested three times with failure types logged.
  • Contracts, labels and delivery notes no longer cite retired models.
